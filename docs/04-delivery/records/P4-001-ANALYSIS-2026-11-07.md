# P4-001 - Analisis awal adapter Adventech

## Pembaruan setelah konfirmasi

Pemilik mengonfirmasi arah pilihan A dan usulan cache PostgreSQL/on-demand pada 2026-11-07. Konfirmasi tersebut tidak menyatakan bahwa bukti hak materi telah tersedia; gate tetap tertutup.

Pemeriksaan lanjutan pada kode resmi Android Adventech menemukan bahwa API quarterly menggunakan `api/v2/{lang}/quarterlies/{id}/index.json` dan lesson menggunakan `api/v2/{lesson}/index.json`. Model `SSQuarterlyInfo` memisahkan `quarterly` dan daftar `lessons`; model `SSLessonInfo` memisahkan `lesson` dan daftar `days`. Metadata lesson/day tidak sendiri memuat isi pelajaran; `SSDay` mempunyai `read_path`/`full_read_path`. Atribusi berada pada `SSQuarterly.credits`. Ini bukti parsial struktur dari klien resmi, belum bukti kontrak lengkap, format isi, batas API, pemetaan kelas, atau hak pengambilan.

Sumber: [quarterly API](https://github.com/Adventech/sabbath-school-android/blob/main/libraries/lessons/api/src/main/kotlin/ss/lessons/api/SSQuarterliesApi.kt), [lesson API](https://github.com/Adventech/sabbath-school-android/blob/main/libraries/lessons/api/src/main/kotlin/ss/lessons/api/SSLessonsApi.kt), [model lesson](https://github.com/Adventech/sabbath-school-android/blob/main/common/models/src/main/java/app/ss/models/SSLessonInfo.kt), [model day](https://github.com/Adventech/sabbath-school-android/blob/main/common/models/src/main/java/app/ss/models/SSDay.kt), [model quarterly](https://github.com/Adventech/sabbath-school-android/blob/main/common/models/src/main/java/app/ss/models/SSQuarterly.kt). Tidak ada endpoint materi yang dipanggil.

Pemeriksaan awal lingkungan menunjukkan Podman belum dapat dihubungi dan perintah Docker tidak tersedia. PostgreSQL disposable belum dijalankan; database bersama tidak di-reset. Kondisi ini masih perlu ditangani sebelum pengujian database.

Pemeriksaan lanjutan: PostgreSQL 18.6 native berhasil diinisialisasi dan dijalankan pada cluster disposable terpisah dengan port 55439; koneksi `select version()` berhasil, lalu cluster dihentikan. Ekstensi pgTAP tidak terpasang pada instalasi native, sehingga koneksi ini belum membuktikan tes pgTAP atau kompatibilitas lingkungan Supabase. Podman belum dapat dihubungi. Klien Android resmi yang diteliti berada pada commit `55405f66a8c555047dc0035747acdcaa371d59fa`: selain endpoint quarterly/lesson v2, `ResourcesApi` juga mendefinisikan endpoint resources v3. Bentuk konten penuh dan pemetaan kelas masih memerlukan pembuktian sebelum parser dan schema final dirancang.

Pada 2026-11-08 pekerjaan dimulai dengan normalizer metadata quarterly v2 berbasis model klien resmi dan fixture sintetis. Pengujian awal gagal pada assertion sebelum implementasi, lalu dua pengujian lulus; suite Node lengkap lulus 417/417 dan ESLint untuk kedua berkas lulus. Komponen ini belum terhubung ke route, fetch, cache atau tampilan; ia belum membuktikan kompatibilitas lengkap upstream dan tidak menyelesaikan issue #50. Implementasi gate, isi lesson, cache PostgreSQL, pengujian disposable dan CI masih diperlukan.

Tindak lanjut 2026-11-08: normalizer juga memeriksa metadata hari pada `SSLessonInfo`, menolak ID duplikat dan path relatif yang mengandung traversal, encoding persen, backslash, atau URL absolut. Dua siklus RED/GREEN menegaskan penolakan ID lesson duplikat dan path tidak aman; 4/4 tes terarah, 419/419 suite Node, ESLint dua berkas, dan `npm run typecheck` lulus. Ini memvalidasi metadata sintetis saja, bukan konten v3 berbasis blok. WSL sedang dalam proses shutdown bersama dan ada proses Podman untuk pekerjaan lain; proses tersebut tidak dihentikan atau di-reset. Tidak ada migration/cache, pengujian database, commit, push, PR, atau CI untuk pekerjaan ini.

Tindak lanjut berikutnya pada 2026-11-08: berdasarkan [adapter tipe blok resmi](https://github.com/Adventech/sabbath-school-android/blob/55405f66a8c555047dc0035747acdcaa371d59fa/libraries/block-kit/model/src/main/kotlin/io/adventech/blockkit/model/adapter/BlockItemJsonAdapterFactory.kt), ditambahkan validasi segmen v3 yang hanya menerima paragraf dan heading, serta menolak keseluruhan segmen bila ada tipe belum didukung, data wajib tidak lengkap, atau ID blok duplikat. Markdown dipertahankan sebagai input tak tepercaya dan belum dirender. RED gagal sesuai assertion sebelum implementasi; 6/6 tes terarah, 421/421 suite Node, ESLint dua berkas, dan typecheck lulus. Tipe lain yang didukung upstream belum diimplementasikan; hasil ini belum membuktikan kompatibilitas dengan materi riil dan bukan pemenuhan lengkap #50.

Tindak lanjut selanjutnya: migration aditif menyiapkan cache pada schema privat dengan RLS dan tanpa grant aplikasi; belum ada jalur aplikasi untuk menulis atau membacanya. Pada PostgreSQL 18.6 disposable, pemeriksaan sebelum migration menyatakan tabel belum ada; setelah migration, pemeriksaan hak akses, RLS, penolakan versi kosong/payload array/status invalid, dan insert sintetis oleh pemilik lulus dalam transaksi rollback. Tes pgTAP repository disiapkan tetapi belum dijalankan karena Podman belum dapat dihubungi dan instalasi PostgreSQL native tidak memiliki pgTAP. Suite Node 421/421, typecheck dan lint lengkap lulus. Build keluar dengan kode 0, tetapi log mencatat kegagalan koneksi ke Supabase lokal pada port 54321; ini bukan bukti integrasi database. Adapter fetch, gate aplikasi dan fallback cache belum terhubung; issue dan PR belum selesai.

## Fondasi gate tertutup (2026-11-08)

- Klien resmi pada commit `55405f66a8c555047dc0035747acdcaa371d59fa` memakai host `https://sabbath-school.adventech.io/` dan endpoint quarterly v2. Adapter server memakai host tetap, ID terbatas, larangan redirect, timeout, batas respons 2 MiB dan UTF-8 ketat. Sumber diuji hanya memakai respons sintetis; endpoint materi tidak dipanggil.
- Entri `server-only` menutup akses secara tetap sampai perubahan terpisah menghubungkan verifikasi hak yang disahkan. Tidak ada route publik atau request nyata. Fungsi refresh/fallback menerima dependency tepercaya dan diuji dengan pengganti sintetis; pemeriksaan hak gagal tertutup, sumber invalid tidak menulis cache, dan fallback hanya digunakan setelah verifikasi hak dan validasi metadata.
- Cache PostgreSQL berada di schema privat, RLS aktif, tanpa grant untuk anon, authenticated, atau service_role. Kode aplikasi belum menghubungkan penyimpanan tersebut; tidak ada cara dari aplikasi untuk menyimpan/membaca materi. Fungsi pgTAP 1.3.3 dipasang hanya di database PostgreSQL 18.6 disposable dan tes `p4_001_sabbath_cache.test.sql` lulus 10/10.
- Batas: baru metadata quarterly/lesson serta blok paragraph/heading yang dikenali; jenis blok lain ditolak. Pemetaan kelas/versi dan format materi sebenarnya belum dibuktikan, TTL belum ditetapkan, dan akses/persistensi/preview/offline tetap bergantung pada bukti hak. Ini bukan penyelesaian seluruh acceptance #50, bukan rilis production dan bukan persetujuan pemakaian materi.
- Verifikasi berikutnya: tes RED/GREEN mencakup pembatasan entri server, sumber palsu, respons invalid, fallback, cache rusak dan pencabutan hak selama pemuatan. Suite Node lengkap 432/432, typecheck dan ESLint lulus; pgTAP cache 10/10 lulus di PostgreSQL disposable. Build keluar 0 dengan kegagalan koneksi ke Supabase lokal yang tidak aktif, sehingga bukan bukti integrasi layanan. Tidak ada request materi nyata. Status CI PR harus diperiksa pada commit perbaikan yang dipush.

## Koneksi PostgreSQL (2026-11-08)

Cache kini terhubung melalui sesi Supabase server dan RPC baca/tulis. Kedua RPC memerlukan Admin aktif dan pemeriksaan hak di database; fungsi gate hak saat ini selalu menolak dan tidak dapat dieksekusi oleh role aplikasi. Gate pada server juga tetap menolak sebelum koneksi database atau fetch dibuat. Tabel privat tetap tidak memiliki grant aplikasi. Membuka gate atau menetapkan cakupan hak adalah pekerjaan P4-005 yang memerlukan keputusan dan migration terpisah.

Penulisan memakai upsert yang hanya menerima timestamp lebih baru. RPC juga memvalidasi ulang bentuk metadata, bahasa, sumber, atribusi, URL, urutan dan keunikan lesson di database, sehingga pemanggilan langsung yang tidak valid tidak menimpa snapshot lama. Tes PostgreSQL disposable menggunakan data sintetis dan mengganti gate menjadi terbuka **hanya di transaksi yang di-rollback**, untuk memverifikasi baca/tulis Admin, penolakan Editor/Admin nonaktif, dan perlindungan dari penimpaan data lama atau invalid. Hasil: tes RPC 26/26 dan tes cache 10/10 lulus. Pengujian memakai PostgreSQL 18.6 dengan pgTAP dan fixture Auth lokal minimal; CI Supabase tetap diperlukan untuk memverifikasi konfigurasi autentikasi sebenarnya. Koneksi ini belum mengesahkan hak, menambah reader, atau menyelesaikan pemetaan seluruh kelas/blok.

Verifikasi perubahan koneksi: RED/GREEN dilakukan untuk adapter RPC dan penolakan metadata tidak lengkap. Suite Node lulus 434/434, typecheck dan lint lulus. Build selesai dengan kode 0 tetapi melaporkan koneksi ke Supabase lokal yang tidak aktif; jalur JavaScript-ke-PostgREST belum diuji end-to-end pada lingkungan lokal. Dua migration diaplikasikan berurutan pada database disposable baru dan kedua tes pgTAP di atas lulus; CI pada commit PR diperlukan sebagai bukti tambahan atas Auth Supabase yang sebenarnya.

Tanggal: 2026-11-07 (Asia/Makassar). Status: usulan untuk konfirmasi pemilik, belum merupakan desain yang disetujui dan belum ada implementasi. Baseline `development`: `b9172cc45faf6e9c66da1bfc2d3ca9dc1ee74ed8` (merge PR #91). Branch analisis: `feature/p4-001-adventech-adapter`.

## Scope yang diusulkan

1. Adapter server-only; browser tidak mengakses upstream. Normalizer/validator hanya memakai kontrak upstream yang telah diverifikasi dan dipatok versinya.
2. Validasi bahasa Indonesia, class, quarter, identifier stabil, judul, urutan, isi, URL aset, attribution, dan version. Data invalid/tidak lengkap tidak menggantikan versi valid terakhir.
3. Read model dan metadata cache: source/version, fetched_at, checksum/ETag bila tersedia, dan status validasi. Fallback hanya ke salinan yang masih diizinkan dan menampilkan waktu pembaruannya; bila tidak ada, hasil unavailable, bukan materi buatan.
4. Gate tertutup secara default: belum melakukan fetch/persistensi materi atau aktivasi publik sampai cakupan izin disahkan. Tes memakai fixture sintetis, bukan menyalin pelajaran sebenarnya.
5. Jika dipilih cache PostgreSQL: migration aditif beserta tipe, grants/RLS dan negative tests; tidak mengubah migration lama atau database yang sedang dipakai bersama. Detail schema menunggu kontrak sumber dan jalur refresh disepakati.
6. Sinkronisasi dokumen hanya berdasarkan bukti. Status kesiapan teknis dibedakan dari izin aktivasi, merge, dan production. #50 tidak dianggap seluruhnya selesai selama acceptance hak/TTL yang relevan masih terbuka.

Di luar scope: katalog/reader baru, unduhan/offline/PWA, akun Member, progres cloud, penjadwal baru, perubahan pastoral, dan deployment/migration production.

## Dependensi dan risiko

- P2 server foundation tersedia. Persetujuan operasional/production Phase 3 tidak disimpulkan dari merge #91; perlu pemilik menetapkan apakah pembangunan mekanisme Phase 4 boleh berjalan sambil gate production tetap dicatat.
- Gate #54 membedakan fetch, tampilan/preview, cache server/persistensi, dan offline. Dokumen PRD/integrasi memuat batas offline, sementara backlog/roadmap menerapkan batas cache yang lebih ketat. Batas ketat tetap berlaku sampai ada keputusan berbukti.
- [README upstream](https://github.com/Adventech/sabbath-school-lessons#copyright) secara eksplisit membahas pembatasan reproduksi/publikasi materi dengan izin tertulis. Keberadaan [MIT license](https://github.com/Adventech/sabbath-school-lessons/blob/stage/LICENSE.md) tidak dipakai untuk menyimpulkan izin materi. Analisis ini hanya membaca dokumentasi/metadata; tidak memanggil endpoint pelajaran sebenarnya.
- Tautan API dari README, `https://adventech-sabbath-school.api-docs.io/v1/getting-started`, mengarah ke halaman umum `https://api-docs.io/` saat diperiksa. Schema respons, host/path API aktif, pemetaan class, batas rate, ETag, dan TTL belum diverifikasi. Tidak mengarang mapping class atau angka TTL. Verifikasi lanjutan dapat membaca kode generator/klien resmi tanpa mengambil materi pelajaran.
- Isi upstream adalah input tidak tepercaya. Kontrak perlu membatasi ukuran/respons/timeout, URL host dan redirect, serta format isi agar tidak menjadi SSRF atau jalur HTML aktif. Format render reader tetap dibahas pada P4-003.
- Cache invalid tidak boleh menimpa last-known-good; izin yang berakhir/dicabut juga harus menghentikan fallback, bukan sekadar menghentikan refresh. Detail cakupan/batas waktu izin belum ditetapkan.
- PostgreSQL/cache menambah permukaan baca/tulis dan operasional refresh; hindari service-role atau RPC baru yang belum diperlukan. Akses, aktor refresh, dan persistence harus diputuskan bersama bentuk cache.

## Alternatif dan rekomendasi

| Pilihan | Dampak | Penilaian |
| --- | --- | --- |
| A. Bangun mekanisme dengan fixture sintetis dan gate aktivasi tertutup | Fondasi teknis dapat maju tanpa mengubah halaman publik atau mengambil materi. Hak, kontrak sumber dan TTL yang belum jelas tetap dicatat; tidak mengklaim seluruh acceptance selesai. | Rekomendasi awal; perlu konfirmasi pemilik sebelum implementasi. |
| B. Dahulukan klarifikasi izin dan kontrak sebelum menulis adapter | Menghindari penyesuaian kode bila format/hak berbeda; kemajuan implementasi menunggu bukti eksternal. | Sesuai bila prioritasnya integrasi yang langsung dapat diaktifkan. |

Untuk penyimpanan, model data dan kebutuhan fallback lintas request lebih mendukung cache PostgreSQL setelah kontraknya jelas. HTTP cache lebih kecil tetapi tidak boleh dianggap otomatis memenuhi kontrol status validasi, penggantian last-known-good, dan pencabutan izin. Pilihan penyimpanan masih usulan, bukan keputusan final. Refresh on-demand lebih kecil daripada menambah scheduler; TTL ditetapkan setelah batas upstream terverifikasi.
