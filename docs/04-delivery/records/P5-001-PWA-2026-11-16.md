# P5-001 (issue #55) — PWA foundation (2026-11-16)

**Status:** Selesai untuk lingkup foundation. Installability dan application shell offline terbukti; pengelolaan data lanjutan milik P5-002 dan offline materi tetap tertutup oleh gate P4-005.

Issue: [#55](https://github.com/adrielwalintukan/Rinegetan-Connect/issues/55). Branch `feature/p5-001-pwa-foundation`.

## Keputusan yang harus diambil sebelum kode

Issue #55 mencatat tiga hal sebagai belum diputuskan dan memerintahkan untuk tidak mengarangnya. Ketiganya ditanyakan ke pemilik dan dijawab pada 2026-11-16:

| Pertanyaan | Keputusan pemilik |
| --- | --- |
| Library / strategi service worker | Service worker **tulis tangan**, tanpa dependency baru |
| Cakupan cache offline | **Hanya shell publik**; reader Sekolah Sabat dan `/pelajari-alkitab` tidak di-cache |
| Indikator versi | **Banner saat versi berubah** dengan tombol "Muat ulang" |

Tanpa jawaban ini, implementasi akan mengubah keputusan pemilik menjadi asumsi implementer — persis yang dilarang issue.

## Yang dibangun

### Manifest dan ikon

`src/app/manifest.ts` menyajikan `/manifest.webmanifest` berisi `name`, `short_name`, `start_url: "/"`, `scope: "/"`, `display: "standalone"`, `lang: "id"`, warna tema navy `#0A2540`, dan tiga ikon: 192 `any`, 512 `any`, 512 `maskable`.

`any` dan `maskable` sengaja dipisah. Satu entri `maskable` saja akan dipotong Android; satu entri `any` saja akan menampilkan kotak bersudut di dalam lingkaran peluncur.

Ikon diturunkan dari `public/icon.svg` lewat `scripts/generate-pwa-icons.mjs`, sehingga lambang gereja tetap punya satu sumber kebenaran. Varian maskable menempelkan karya pada kanvas navy, bukan memperbesarnya, supaya latar membulat dari ikon sumber tidak tampak sebagai kotak kedua.

`layout.tsx` menambahkan `apple-icon-180.png` (iOS mengabaikan ikon manifest saat "Add to Home Screen") dan `viewport.themeColor`.

### Application shell

`public/sw.js` **dihasilkan** oleh `scripts/generate-sw.mjs` dari `src/lib/pwa/shell.mjs`. Alasannya bukan kerapian: test memeriksa kebijakan di modul, jadi worker yang ditulis ulang terpisah bisa berperilaku lain dari yang diuji. Test `the committed worker is the generated policy` menolak worker yang disunting tangan.

| Keputusan | Alasan |
| --- | --- |
| Nama cache memuat build id | Dua build tidak pernah berbagi cache, sehingga `activate` bisa menghapus seluruh cache lain tanpa menebak mana yang basi |
| Build id dari commit, bukan konstanta | Konstanta yang di-bump manual akan lupa di-bump tepat pada rilis yang membutuhkannya, dan gagal secara diam-diam |
| HTML network-first | Perubahan konten harus terlihat pada kunjungan berikutnya, bukan pada rilis berikutnya; cache hanya jaring saat offline |
| `/_next/static/*` cache-first | Nama berkas memuat hash isi, jadi tidak mungkin menyajikan versi salah |
| Daftar tolak eksplisit | Kegagalan kedua arah tidak simetris: halaman tidak ter-cache hanya lambat, sedangkan respons staf ter-cache adalah insiden privasi |

Daftar tolak menutup `/staff`, `/api`, `/auth`, `/sekolah-sabat`, dan `/pelajari-alkitab`. Hanya navigasi (`request.mode === "navigate"`) ke rute shell yang di-cache, sehingga `fetch()` ke URL yang sama tidak menyeret data ke cache.

### Versioning, update, dan recovery

- `next.config.ts` menurunkan build id dari commit (`VERCEL_GIT_COMMIT_SHA` di Vercel, `git rev-parse` lokal) dan memakainya untuk `generateBuildId` serta `NEXT_PUBLIC_BUILD_ID`.
- `/sw.js` dikirim `Cache-Control: no-cache, no-store, must-revalidate`; skrip worker yang ter-cache akan memaku pengunjung pada shell lama.
- `activate` menghapus setiap cache yang bukan milik build berjalan, lalu `clients.claim()`.
- `SKIP_WAITING` dan `RESET_CACHE` ditangani di worker. `RESET_CACHE` adalah jalur pemulihan bila shell rusak: seluruh cache dihapus dan dibangun ulang dari jaringan.
- Banner `role="status"` muncul **hanya** saat worker baru selesai `installed` sementara sudah ada controller aktif. Pada instalasi pertama tidak ada yang perlu ditinggalkan, jadi banner tidak muncul.

## Cacat yang ditemukan oleh test dan diperbaiki

Test browser menemukan bug nyata sebelum sempat dirilis: `clients.claim()` pada kunjungan **pertama** juga memicu `controllerchange`, dan listener yang ada memuat ulang halaman tanpa syarat. Artinya setiap pengunjung baru akan mengalami satu reload yang tidak ia minta.

Perbaikannya memisahkan keputusan ke `src/lib/pwa/update.mjs`:

- `shouldAnnounceUpdate()` — hanya `installed` + sudah ada controller.
- `shouldReloadOnControllerChange()` — hanya bila halaman memang sudah dikendalikan saat dimuat, dan belum pernah reload.

Keduanya diuji sebagai fungsi murni, dan komponen diuji memakai fungsi itu (bukan menyalin logikanya), sehingga regresi ini tidak bisa kembali tanpa menggagalkan test.

## Batas verifikasi

- Installability dinilai dari manifest, ikon, dan worker yang aktif. Prompt instalasi sungguhan hanya muncul di browser dengan UI, dan keputusan menampilkannya milik browser; tidak ada tangkapan layar prompt yang diklaim.
- Banner update diuji lewat fungsi keputusan dan pemakaiannya di komponen. Penggantian worker sungguhan tidak dapat dipentaskan di Playwright (skrip worker tidak dapat diintersepsi dan blob URL tidak dapat diregistrasi), jadi perilaku banner saat rilis nyata belum pernah teramati di browser.
- Offline materi **tidak** diaktifkan. Reader Sekolah Sabat dan `/pelajari-alkitab` berada di daftar tolak, dan gate `OFFLINE_ENABLED` P4-004 tetap `false`.
- Tidak ada perubahan schema, migration, grant, atau RLS.
