# Catatan OPS-SEO — Sitemap, Robots, Canonical, dan Kartu Sosial

- **Tanggal:** 14 November 2026
- **Issue:** OPS-SEO (#72)
- **Perubahan kode:** PR #106 (squash ke `development`), PR #107 (rilis ke `main`), PR ini (`og:url` rute pembaca)
- **Lanjutan:** PR ini menambahkan judul beranda deskriptif, ikon situs, dan structured data `Church`
- **Persetujuan:** pemilik repository menyetujui squash merge, rilis ke production, dan perbaikan lanjutan sebelum tiap langkah dijalankan.

Catatan ini tidak memuat kredensial, token, atau data pribadi.

## Kondisi sebelum

Diukur pada `development` `e92f855` dan production `main` `4c13fed`:

| Pemeriksaan | Hasil sebelum |
| --- | --- |
| `/sitemap.xml` | 404, tidak ada berkas rute |
| `/robots.txt` | 404, tidak ada berkas rute |
| `rel="canonical"` | tidak ada di rute publik mana pun |
| `og:image` di 7 halaman publik | tidak ada, padahal `twitter:card=summary_large_image` |
| `og:url` di 7 halaman publik | tidak ada |
| `og:url` di `/pelajari-alkitab` | ada, karena halaman ini tidak mendeklarasikan `openGraph` sendiri |

Penyebab `og:url` hilang: setiap halaman publik mendeklarasikan `openGraph` sendiri, dan Next.js **menimpa** `openGraph` root, bukan menggabungkannya. Akibatnya `url` yang diset di `layout.tsx` tidak pernah sampai ke HTML kecuali pada halaman yang tidak punya `openGraph`.

## Batas dan tindak lanjut

- Rute `pelajari-alkitab/[courseSlug]` dan `/[lessonSlug]` belum dapat diuji runtime karena belum ada kursus Published di production. Perubahannya mengikuti pola yang sama dengan halaman katalog yang sudah terverifikasi.
- Rute `sekolah-sabat/[quarterId]` dan turunannya belum punya `canonical` maupun `openGraph` sendiri, sehingga mewarisi metadata root. Ini kondisi lama, di luar lingkup issue ini, dan layak menjadi issue terpisah.
- Pratinjau `og:image` pada scraper WhatsApp/Facebook belum diuji langsung; cache pratinjau scraper mungkin perlu di-refresh manual.
- Sitemap sudah disubmit ke Google Search Console pada 14 November 2026: status **Success**, 8 halaman terbaca. Langkah pengulangan ada di [DEPLOYMENT-RUNBOOK](../DEPLOYMENT-RUNBOOK.md).

## Lanjutan 14 November 2026 - judul beranda, ikon, structured data

Setelah sitemap disubmit, diagnosis production menunjukkan tiga hal yang masih menahan tampilan di Google:

| Berkas | Perubahan |
| --- | --- |
| `src/app/(public)/page.tsx` | `title: { absolute: "GMAHK Rinegetan — Gereja Advent Tondano, Minahasa" }` agar templat root tidak menambah akhiran, dan `openGraph.title` disamakan |
| `src/app/icon.svg` | ikon 512x512 baru: kotak navy `#0A2540` bersudut membulat dengan lambang Advent amber `#E5A93C`, memakai jalur SVG yang sama dengan `AdventistSymbol.jsx` sehingga tidak ada berkas biner di repo |
| `src/app/layout.tsx` | satu blok JSON-LD `Church` untuk seluruh situs |

Isi structured data hanya memakai nilai terverifikasi dari `src/data/content.js`:

- `name`, `alternateName`, `description`, `url`.
- `logo` -> `/icon.svg`, `image` -> `/opengraph-image`.
- `address` tingkat kawasan: `Rinegetan`, `Tondano`, `Sulawesi Utara`, `ID`.
- `geo` dari `CHURCH.mapsQuery` (`1.2980427,124.9081001`) dan `hasMap` dari tautan pin yang sama.
- `openingHoursSpecification` memakai `opens` saja: Sabat 08:45 dan 10:15, Rabu 19:00, Jumat 18:30. Tidak ada `closes` karena jam selesai belum pernah dikonfirmasi.

`telephone`, `email`, `whatsapp`, dan nomor jalan tetap tidak diisi. Test `P2-304` sekarang menolak JSON-LD yang memuat `telephone` atau `streetAddress: "Jl...` agar data karangan tidak lolos.

## Lanjutan 16 November 2026 — ikon hasil pencarian Google (favicon SERP)

Situs sudah muncul di posisi teratas untuk `gmahk rinegetan`, tetapi Google masih menampilkan globe generik di samping hasil pencarian. Ini bukan kegagalan structured data: `@graph` `WebSite` + `Church` dan `sameAs` sudah terverifikasi live. Penyebabnya adalah kelayakan favicon. Google hanya memakai ikon yang persegi dan berukuran kelipatan 48 piksel (48, 96, 144, 192, ...), sedangkan satu-satunya ikon yang tersedia sebelumnya adalah `icon.svg` dengan `viewBox` 512 dan tidak ada PNG di akar situs.

| Berkas | Perubahan |
| --- | --- |
| `src/app/icon.svg` -> `public/icon.svg` | Ikon SVG dipindahkan ke `public/` agar tetap dilayani di `/icon.svg` (dipakai `logo` structured data) tanpa diproses Next sebagai metadata ikon |
| `public/icon-192.png`, `public/icon-48.png` | PNG persegi 192 dan 48 piksel dari jalur SVG yang sama, latar navy penuh tanpa transparansi dan tanpa sudut membulat, karena Google memasang ikon pada tile sendiri |
| `src/app/layout.tsx` | `metadata.icons` mendeklarasikan `icon-192.png` (`192x192`), `icon-48.png` (`48x48`), lalu `icon.svg`; `shortcut` memakai `icon-48.png` |
| `tests/p2-304-public-queries-metadata.test.mjs` | Test membaca header PNG dan memastikan lebar/tinggi persis 48 dan 192, plus memastikan kedua URL dideklarasikan di layout |
| `docs/04-delivery/DEPLOYMENT-RUNBOOK.md` | Pemeriksaan rilis menambahkan `/icon-192.png` dan `/icon-48.png` |

Hasil render `<head>` pada build lokal:

```
<link rel="shortcut icon" href="/icon-48.png"/>
<link rel="icon" href="/icon-192.png" type="image/png" sizes="192x192"/>
<link rel="icon" href="/icon-48.png" type="image/png" sizes="48x48"/>
<link rel="icon" href="/icon.svg" type="image/svg+xml"/>
```

Catatan operasional: pemilihan ikon di hasil pencarian dilakukan Google dan baru berubah setelah halaman dirayapi ulang. Setelah rilis, minta pengindeksan ulang beranda lewat Google Search Console; tampilan ikon biasanya menyesuaikan dalam hitungan hari sampai beberapa minggu. Tidak ada cara memaksa perubahan ini dari sisi kode.
