# Catatan OPS-GIT — Ruleset main/development dan Penghapusan Branch

- **Tanggal:** 24 Oktober 2026
- **Issue:** OPS-GIT (#69)
- **Perubahan kode:** PR #82, job CI Release source branch dan pembaruan [GIT-WORKFLOW](../GIT-WORKFLOW.md#perlindungan-github)
- **Persetujuan:** pemilik repository menyetujui rencana (dua ruleset tanpa bypass, check sumber PR rilis, penghapusan branch otomatis) sebelum pengaturan diubah.

Catatan ini tidak memuat kredensial, token, atau data pribadi.

## Kondisi sebelum

Pemeriksaan baca-saja 23–24 Oktober: `main` dan `development` tidak protected (API branch protection 404), daftar ruleset kosong, `delete_branch_on_merge=false`. Repository publik milik akun pribadi, sehingga ruleset tersedia.

## Pengaturan yang diterapkan

| Ruleset | Target | Aturan |
| --- | --- | --- |
| `development` | `refs/heads/development` | deletion, non_fast_forward, pull_request (0 approval), required_status_checks: Frontend Quality Gate & Build, Database pgTAP & RLS Tests, Browser regression (Playwright), Backend syntax |
| `main` | `refs/heads/main` | Sama dengan `development`, ditambah Release source branch |

- Enforcement `active`; `bypass_actors` kosong; API melaporkan `current_user_can_bypass=never` untuk kedua ruleset.
- Required checks terikat ke aplikasi GitHub Actions; `strict_required_status_checks_policy=false`.
- 0 approval karena hanya ada satu maintainer, dan penulis PR tidak bisa menyetujui PR sendiri.
- `delete_branch_on_merge=true`.
- Nama check diambil dari check run aktual commit `4d8c660` dan PR #82. `Supabase Preview` (selalu skipped) dan check Vercel tidak diwajibkan.

## Verifikasi

| Pemeriksaan | Hasil |
| --- | --- |
| Aturan efektif per branch (`GET rules/branches/{branch}`) | Sesuai tabel di atas untuk `development` dan `main`. |
| Check Release source branch | Lulus di PR #82 (base `development`, langkah dilewati). |
| Ruleset menahan merge | PR #82 berstatus `BLOCKED` selama check wajib masih berjalan. |
| Logika guard sumber PR | Skrip step diambil apa adanya dari `ci.yml` dan dijalankan lokal dengan `bash`: `development` dari repository ini exit 0; `chore/x` dari repository ini, `development` dari fork, dan `feature/y` dari fork masing-masing exit 1. |

Direct push dan force push tidak diuji, sesuai issue: penolakannya dijamin oleh aturan ruleset yang dibaca ulang di atas.

## Batas dan tindak lanjut

- Logika guard sudah diuji lokal (tabel di atas), tetapi kondisi `if` step (event `pull_request` dengan base `main`) baru teramati pada PR nyata. Pada PR rilis pertama, pastikan step berjalan (bukan dilewati) dan lulus untuk `development`.
- Penghapusan branch otomatis belum diamati pada PR rilis `development` → `main`. Ruleset deletion seharusnya mencegah `development` terhapus; periksa pada rilis berikutnya.
- Admin repository tetap bisa mengubah atau menonaktifkan ruleset. Perubahan darurat dicatat sebagai catatan baru.
