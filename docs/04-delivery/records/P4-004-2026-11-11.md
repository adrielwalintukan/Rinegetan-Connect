# P4-004 — Popup ayat di bacaan Sekolah Sabat

Tanggal: 2026-11-11 (Asia/Makassar). Lanjutan tinjauan pemilik pada PR #96. Issue #52 tetap terbuka.

## Permintaan

Di bacaan harian Sekolah Sabat, referensi ayat seperti “Mat. 7: 5” dapat diklik dan menampilkan popup berisi bunyi ayat tersebut.

## Sumber bunyi ayat

Respons `…/days/<day>/read/index.json` sudah memuat `bible`, yaitu array `{ name, verses }` berisi bunyi ayat untuk referensi yang dipakai hari itu. Jadi fitur ini **tidak menambah request baru** dan tidak memanggil API Alkitab pihak ketiga.

Probe pada 5 pelajaran triwulan `2026-04` (35 hari): 32 hari menyertakan `bible`, 198 referensi di konten, dan 198 di antaranya punya bunyi ayat — tidak ada referensi yang kehilangan teks. Nilai `verses` memakai tag `h2` (judul referensi) dan `sup` (nomor ayat) saja.

## Keamanan

- `verses` disanitasi dengan daftar tag konten tanpa `a`/`button` dan tanpa atribut apa pun; script/style/iframe/svg/img/event handler hilang.
- Referensi yang bunyi ayatnya tidak ada tetap teks biasa, jadi tidak muncul tombol yang tidak berbuat apa-apa.
- Tidak ada `dangerouslySetInnerHTML` baru tanpa sanitasi: HTML artikel dan HTML ayat sama-sama berasal dari normalizer server.

## Aksesibilitas

`<dialog>` native memberi focus trap, penutupan dengan Escape, dan pengembalian fokus ke tombol asal tanpa kode sendiri. Ada tombol tutup berlabel “Tutup ayat”, `aria-label` dialog memakai teks referensi yang diklik, dan backdrop dapat diklik untuk menutup.

## Perbaikan: popup tidak bisa digulir (2026-11-11)

Laporan pemilik: “saat saya coba scroll yang terscroll adalah bagian belakang”. Gejala ini diukur dulu dengan loop umpan balik Playwright terhadap build produksi: roda mouse di atas dialog, lalu bandingkan `dialog.scrollTop` dan `window.scrollY` sebelum/sesudah.

Hasil awal (merah): di 390px dan 1440px `dialogScrollTop` tetap `[0, 0]` sementara `pageScrollY` naik (`[1734, 2446]` dan `[913, 1629]`). Kasus kontrol dengan `prefers-reduced-motion: reduce` — yang mematikan Lenis di `PublicClientRuntime` — berwarna hijau. Itu menyempitkan penyebab ke satu tersangka.

Hipotesis yang terbukti benar: **Lenis merebut event wheel di atas `<dialog>`** karena dialog tidak punya `data-lenis-prevent`, dan `allowNestedScroll` tidak diaktifkan. Prediksi “menambahkan atribut itu saja, tanpa perubahan lain, membalik hasilnya” diuji dengan probe yang menyuntik atribut saat runtime: `patched: false` → gagal, `patched: true` → lolos. Hipotesis alternatif (dialog bukan scroll container; body scroll lock tidak jalan; `showModal()` tidak memberi inert) terbantah oleh data loop yang sama.

Perbaikan: satu atribut `data-lenis-prevent` pada `<dialog>`, plus komentar alasannya. Tidak ada perubahan lain.

Verifikasi setelah perbaikan, di 320/390/1440px: roda ke bawah menggulir dialog (`0 → 720/711/347`), halaman diam, roda ke atas menggulir balik, Escape menutup, fokus kembali ke tombol asal, dan halaman bisa digulir lagi setelah popup ditutup. Loop yang sama sekarang hijau di semua kasus.

Regression test di CI mengunci atribut itu pada HTML server (`toHaveAttribute("data-lenis-prevent", "true")`). Perilaku wheel-nya sendiri tidak bisa diuji di suite fixture statis yang tidak menjalankan bundle klien; itu terverifikasi lewat loop di atas terhadap build produksi.

## Batas

- Popup hanya tersedia pada bacaan harian, karena hanya respons itu yang membawa `bible`. Daftar pelajaran dan daftar hari tidak memuat ayat.
- Teks ayat mengikuti terjemahan yang dipilih Adventech; aplikasi tidak menyediakan pemilih terjemahan.
- Bila upstream tidak mengirim `bible` untuk suatu hari, referensi tetap teks biasa — tidak ada fallback ke API Alkitab lain.
