## 5. Restore drill (nonproduksi, lokal, 15 Okt)

Lingkungan: Supabase lokal di Podman (VM 2 GiB, service minimal: db, auth, rest, storage, kong). Durasi ±25 menit termasuk penyelarasan versi; pemuatan data 3 detik.

| Pemeriksaan | Production | Hasil restore |
| --- | --- | --- |
| auth.users / profiles / staff_roles | 2 / 2 / 2 | 2 / 2 / 2 |
| announcements / events / departments / schedules | 2 / 0 / 0 / 0 | sama |
| media_assets / consent_records / storage.objects | 3 / 2 / 3 | sama |
| audit_logs | 14 | 14 |
| Policy RLS public / tabel tanpa RLS | 43 / 0 | 43 / 0 |
| Migration terakhir | `20261015090000` | sama |
| Checksum file media | — | 3/3 cocok manifest |

Uji akses pada hasil restore:

| Uji | Publik (anon) | Editor dummy |
| --- | --- | --- |
| Pengumuman | 1 (hanya terbit) | 2 (termasuk draft) |
| Foto | 1 (terbit + consent approved) | 3 |
| Log audit | ditolak | 0 baris (khusus Admin) |
| File foto draft | ditolak | dapat dibaca |
| `delete_staff` | — | ditolak `not_admin` |

Temuan drill (dicatat di runbook):

1. Supabase meng-upgrade Auth/Storage production secara otomatis; `supabase/.temp/*-version` lokal menjadi basi. Restore gagal sampai versi Auth disamakan (v2.197.0, cek `GET /auth/v1/health`).
2. Storage production memiliki kolom (`buckets.lifecycle_configuration*`) yang belum ada di image publik terbaru. Restore memakai penyaring yang hanya membuang kolom/tabel yang **seluruhnya NULL/kosong** dan berhenti bila ada nilai.
3. Bucket bawaan migration bentrok dengan baris dump — `truncate storage.buckets cascade` dalam transaksi yang sama.
4. Data dimuat sebagai `supabase_admin` (tabel storage dimiliki `supabase_storage_admin`).
5. Login email lokal mati karena `auth.email.enable_signup = false` diterjemahkan CLI menjadi provider email nonaktif; uji RLS memakai JWT lokal. Tidak memengaruhi production.

## 7. Tindak lanjut terbuka

1. Salin kedua arsip `.tar.age` ke penyimpanan gereja (Drive belum tersedia) — saat ini arsip dan private key hanya di satu laptop.
2. Penanggung jawab backup kedua membuat key `age` sendiri; enkripsi ulang backup berikutnya ke dua penerima.
3. Pastikan secret key yang sempat tertempel di chat telah dicabut di dashboard Supabase.
4. Proteksi password bocor (HaveIBeenPwned) Supabase Auth belum aktif — cek ketersediaan di paket.
5. Region fungsi Vercel `iad1` vs database Singapura — pertimbangkan `sin1`.
6. Hapus media permanen belum menghapus objek Storage; izin unduh tingkat album belum punya UI.
7. Foto "Global Youth Day" berstatus terbit dengan consent Pending (terbit sebelum aturan baru) — perbaiki consent atau kembalikan ke Draft.
