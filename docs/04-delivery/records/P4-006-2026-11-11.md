# P4-006 — Catatan pribadi per hari bacaan Sekolah Sabat

Tanggal: 2026-11-11 (Asia/Makassar). Lanjutan dari PR #96 yang sudah merge ke `development` (`c2280be`).

## Permintaan

Pemilik meminta kemampuan mencatat di bagian pelajaran Sekolah Sabat. Sebelum dikerjakan, backlog dan seluruh issue diperiksa: **fitur ini tidak ada di issue mana pun** — bukan pekerjaan tertunda, melainkan permintaan baru.

## Keputusan yang disepakati

| Pertanyaan | Keputusan |
| --- | --- |
| Penyimpanan | Lokal di browser saja (`localStorage`). Tanpa akun, tanpa Supabase. |
| Cakupan | Satu catatan per **hari bacaan** (bukan per pelajaran, bukan per ayat). |
| Bentuk UI | Panel “Catatan saya” yang bisa dibuka-tutup, tertutup secara default. |
| Penempatan kerja | Issue dan PR terpisah dari #96. |

Alasan penyimpanan lokal: acceptance issue #52 secara eksplisit menyatakan *“Tidak menyimpan identitas/progres di Supabase”* dan menempatkan *“akun Member/progres cloud”* sebagai non-scope. Menyimpan catatan di server akan melanggar acceptance issue yang baru saja diselesaikan.

## Keamanan dan ketahanan

- State dibangun ulang dari nol saat dibaca (`parseNotesState`), sehingga metadata asing di `localStorage` tidak pernah masuk ke state tepercaya. Key yang tidak berbentuk `<triwulan>/<pelajaran>/<hari>` dibuang.
- Catatan dikosongkan berarti entri **dihapus**, bukan disimpan sebagai string kosong.
- Panjang dibatasi 4000 karakter per hari; pemotongan dilakukan di modul, bukan hanya lewat `maxLength` di UI.
- Tidak ada `dangerouslySetInnerHTML`, tidak ada request jaringan, tidak ada data yang meninggalkan perangkat.
- Bila browser menolak storage (mode privat/kebijakan), panel memberi tahu bahwa catatan tidak tersimpan, bukan gagal diam-diam.

## Perilaku yang diverifikasi di build produksi

Terhadap `/sekolah-sabat/2026-04/07/05` di 390px:

- Panel tertutup saat pertama dimuat; textarea tidak ada di DOM sampai dibuka.
- Mengetik menyimpan ke `localStorage` dalam ±600 ms; isi bertahan setelah reload.
- Panel tetap tertutup setelah reload, dan header menunjukkan “Ada catatan”.
- Hari lain punya catatan sendiri (kosong).
- “Hapus catatan” mengosongkan storage, bukan hanya textarea.
- Terbuka lewat keyboard (Enter) dan lewat klik.
- axe WCAG 2.2 AA: tanpa violation saat panel terbuka; tanpa overflow horizontal.

Satu bug ditemukan saat pengujian dan diperbaiki sebelum commit: mengetik lalu langsung berpindah halaman dalam <600 ms bisa kehilangan tulisan, karena timer debounce dibatalkan saat unmount. Sekarang ada flush saat unmount; skenario “ketik lalu klik Hari berikutnya” diverifikasi menyimpan catatan dengan benar.

## Batas

- Catatan hanya ada di perangkat/browser ini. Hilang bila data situs dibersihkan, mode privat ditutup, atau pengguna berganti perangkat. Ini dinyatakan di UI.
- Tidak ada sinkronisasi, ekspor, atau pencarian catatan. Tidak diminta, dan sengaja tidak dibuat.
- Catatan tidak terhubung ke ayat tertentu di popup; satu catatan per hari.
- Kuartal lama tetap dapat dibaca, tetapi catatan tetap disimpan per kunci hari sehingga tidak hilang saat kuartal berganti.
