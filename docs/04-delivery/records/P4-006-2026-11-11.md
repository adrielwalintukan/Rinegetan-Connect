# P4-006 — Catatan pribadi per hari bacaan Sekolah Sabat

Tanggal: 2026-11-11 (Asia/Makassar). Lanjutan dari PR #96 yang sudah merge ke `development` (`c2280be`).

## Permintaan

Pemilik meminta kemampuan mencatat di bagian pelajaran Sekolah Sabat. Sebelum dikerjakan, backlog dan seluruh issue diperiksa: **fitur ini tidak ada di issue mana pun** — bukan pekerjaan tertunda, melainkan permintaan baru.

## Keputusan yang disepakati

| Pertanyaan | Keputusan |
| --- | --- |
| Penyimpanan | Lokal di browser saja (`localStorage`). Tanpa akun, tanpa Supabase. |
| Cakupan | Satu catatan per **hari bacaan** (bukan per pelajaran, bukan per ayat). |
| Bentuk UI | Panel “Catatan saya” yang bisa dibuka-tutup, tertutup secara default. |
| Penempatan kerja | Issue dan PR terpisah dari #96. |

Alasan penyimpanan lokal: acceptance issue #52 secara eksplisit menyatakan *“Tidak menyimpan identitas/progres di Supabase”* dan menempatkan *“akun Member/progres cloud”* sebagai non-scope. Menyimpan catatan di server akan melanggar acceptance issue yang baru saja diselesaikan.

## Keamanan dan ketahanan

- State dibangun ulang dari nol saat dibaca (`parseNotesState`), sehingga metadata asing di `localStorage` tidak pernah masuk ke state tepercaya. Key yang tidak berbentuk `<triwulan>/<pelajaran>/<hari>` dibuang.
- Catatan dikosongkan berarti entri **dihapus**, bukan disimpan sebagai string kosong.
- Panjang dibatasi 4000 karakter per hari; pemotongan dilakukan di modul, bukan hanya lewat `maxLength` di UI.
- Tidak ada `dangerouslySetInnerHTML`, tidak ada request jaringan, tidak ada data yang meninggalkan perangkat.
- Bila browser menolak storage (mode privat/kebijakan), panel memberi tahu bahwa catatan tidak tersimpan, bukan gagal diam-diam.

## Perilaku yang diverifikasi di build produksi

Terhadap `/sekolah-sabat/2026-04/07/05` di 390px:

- Panel tertutup saat pertama dimuat; textarea tidak ada di DOM sampai dibuka.
- Mengetik menyimpan ke `localStorage` dalam ±600 ms; isi bertahan setelah reload.
- Panel tetap tertutup setelah reload, dan header menunjukkan “Ada catatan”.
- Hari lain punya catatan sendiri (kosong).
- “Hapus catatan” mengosongkan storage, bukan hanya textarea.
- Terbuka lewat keyboard (Enter) dan lewat klik.
- axe WCAG 2.2 AA: tanpa violation saat panel terbuka; tanpa overflow horizontal.

Satu bug ditemukan saat pengujian dan diperbaiki sebelum commit: mengetik lalu langsung berpindah halaman dalam <600 ms bisa kehilangan tulisan, karena timer debounce dibatalkan saat unmount. Sekarang ada flush saat unmount; skenario “ketik lalu klik Hari berikutnya” diverifikasi menyimpan catatan dengan benar.

## Addendum: temuan review PR #97

Review pemilik pada HEAD `2eb3bcb` memberi dua temuan P2. Keduanya diperiksa, bukan diterima begitu saja.

### Temuan 1 — flush saat unmount tidak menjamin simpan pada navigasi dokumen penuh (valid, diperbaiki)

Klaimnya benar dan perbaikan sebelumnya **tidak cukup**. Flush lama hanya berjalan di cleanup React. Tombol “Hari berikutnya”/“Hari sebelumnya” di `SabbathReader.jsx` adalah `<a>` biasa, jadi browser membongkar dokumen dan cleanup React tidak dijalankan.

Bukti sebelum perbaikan, dengan navigasi dijalankan pada task yang sama sehingga debounce 600 ms tidak mungkin sempat berjalan:

```
probe: navigating
{"kept":false,"raw":null}
RED: note lost on immediate full-document navigation
```

Pengecekan “ketik lalu klik Hari berikutnya” yang saya lakukan sebelum commit ternyata **lulus palsu**: kliknya memakan waktu lebih dari 600 ms, sehingga timer sempat menulis lebih dulu. Itu tepat seperti yang ditulis reviewer.

Perbaikan di `SabbathNotes.jsx`: flush dipusatkan pada satu fungsi `flush`, lalu dipanggil dari tiga jalur — `pagehide` (navigasi dokumen penuh), `visibilitychange` saat tab menjadi `hidden` (tab dibuang saat di latar), dan cleanup unmount (navigasi sisi klien, saat `pagehide` tidak menyala).

### Temuan 2 — belum ada E2E berhidrasi untuk panel catatan (valid, diperbaiki)

Benar: suite `sabbath-reader.spec.ts` memakai HTML fixture statis tanpa bundel klien, sehingga hanya memeriksa markup server.

Seam yang dipakai: `tests/helpers/adventech-stub.cjs` mengganti `globalThis.fetch` di proses server Next untuk rute Adventech saja, dimuat lewat `--require` oleh `tests/helpers/adventech-stub-server.mjs`. Halaman reader asli tetap dirender dan dihidrasi apa adanya; tidak ada kode produk yang diubah dan tidak ada jaringan. `tests/visual/sabbath-notes.spec.ts` (config `sabbath-notes.config.ts`) menjalankan lima alur: buka panel dan persistensi lintas reload, hapus, pindah hari, storage ditolak, serta axe + overflow di 320px.

Test navigasi dokumen terbukti menangkap bug: dengan listener `pagehide` dicabut sementara, test gagal pada asersi penyimpanan; dengan perbaikan dipasang, test lulus. Jadi test ini benar-benar menjaga regresi, bukan sekadar ada.

Satu masalah ditemukan saat menyiapkan suite ini dan diperbaiki sebelum dianggap selesai: `unstable_cache` Next menyimpan respons Adventech selama satu jam. Di CI, suite reader berjalan tepat sebelum suite catatan dan memakai jaringan nyata, sehingga cache itu sudah terisi dan stub tidak pernah dipanggil — halaman menyajikan konten asli dan panel catatan tidak ada. Gejalanya muncul sebagai "element not found", yang menyesatkan. Sekarang server test membersihkan `.next/cache/fetch-cache` sebelum start, dan suite memeriksa judul hari dari stub lebih dulu sehingga cache basi melaporkan "Materi belum tersedia", bukan kegagalan yang salah alamat. Diverifikasi dengan menjalankan suite reader (jaringan nyata, lima entri cache) lalu suite ini, persis urutan di CI.

Langkah CI baru: `Sabbath notes flows (hydrated panel, localStorage, full-document navigation)` di `.github/workflows/ci.yml`, berjalan setelah suite reader dan tetap memakai bundel yang sudah dibangun.

### Catatan tentang status CI

Lima run berurutan gagal di langkah `Install Chromium` karena runner tidak bisa me-resolve `security.ubuntu.com`, `archive.ubuntu.com`, dan `azure.archive.ubuntu.com`; seluruh langkah test berstatus `skipped`, jadi tidak ada kode aplikasi yang dieksekusi. Penyebabnya outage DNS Canonical yang dilaporkan di [actions/runner-images#15296](https://github.com/actions/runner-images/issues/15296) dan dikonfirmasi GitHub staff pada 16:23 UTC. Tiga bukti bahwa ini lingkungan, bukan perubahan di PR ini: langkah `Install Chromium` tidak berubah sejak run hijau terakhir `9a4de4a` (diff `ci.yml` hanya penambahan satu langkah suite catatan), image runner identik di run hijau dan run gagal (`ubuntu26/20261101.186`), dan merge commit PR #96 `c2280be` ikut gagal dengan error yang sama.

Rerun `--failed` pada 17:07 UTC berhasil setelah outage pulih: run [43056694873](https://github.com/adrielwalintukan/Rinegetan-Connect/actions/runs/43056694873) **success**, seluruh langkah browser job berjalan, dan `Sabbath notes flows` melaporkan `5 passed (7.3s)` — bukan `skipped`. Tidak ada perubahan pada `ci.yml` maupun kode produk untuk mencapai ini. `mergeStateStatus` PR menjadi `CLEAN`.

## Batas

- Catatan hanya ada di perangkat/browser ini. Hilang bila data situs dibersihkan, mode privat ditutup, atau pengguna berganti perangkat. Ini dinyatakan di UI.
- Tidak ada sinkronisasi, ekspor, atau pencarian catatan. Tidak diminta, dan sengaja tidak dibuat.
- Catatan tidak terhubung ke ayat tertentu di popup; satu catatan per hari.
- Kuartal lama tetap dapat dibaca, tetapi catatan tetap disimpan per kunci hari sehingga tidak hilang saat kuartal berganti.
